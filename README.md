# Диспетчер задач

[![build](https://github.com/DileSoft/fast-task-manager/actions/workflows/build.yml/badge.svg)](https://github.com/DileSoft/fast-task-manager/actions/workflows/build.yml)

Быстрый аналог первых двух вкладок диспетчера задач Windows 10 — «Процессы» и
«Производительность». Написан на Rust, без WMI и без .NET.

* Один исполняемый файл `tm.exe` (~4 МБ), без установки.
* Запуск до появления окна — около 0.3 с, в покое — ~0.5 % суммарной загрузки
  4-ядерного CPU (обновление раз в секунду), ~85 МБ RAM (включая буферы GPU).
* Список процессов виртуализован: 500+ строк прокручиваются без просадок.

## Возможности

### Вкладка «Процессы»

* Группы как в Windows: **Приложения**, **Фоновые процессы**, **Процессы Windows**;
  раскрытие групп и дерева дочерних процессов, суммы по группе.
* Столбцы: имя (с иконкой), состояние, ЦП, память, диск, сеть, ГП,
  пользователь, потоки, PID, описание. Набор столбцов настраивается.
* Сортировка по любому столбцу, поиск по имени/PID/описанию/заголовку окна.
* Контекстное меню: снять задачу, снять дерево процессов, открыть расположение
  файла, свойства, копировать имя/PID/путь.
* «Снять задачу»: для приложений с окном — мягкое `WM_CLOSE`, иначе
  `TerminateProcess`. Для критических процессов спрашивается подтверждение.
* Скорость обновления: высокая (0.5 с), обычная (1 с), низкая (2 с), пауза.
* Горячие клавиши: `Ctrl+F` — поиск, `Delete` — снять задачу, `F5` — обновить
  снимок немедленно.

### Вкладка «Производительность»

* ЦП: общая загрузка, график по каждому ядру, частота, процессы/потоки/
  дескрипторы, время работы, режим ядра.
* Память: занято/доступно, состав (в работе/кэш/свободно/изменённые), коммит, пулы.
* Диск: активное время, чтение/запись, средний отклик, ёмкость.
* Сеть: приём/передача, пропускная способность адаптера.
* ГП: загрузка, выделенная/общая память (при наличии счётчиков GPU Engine).

## Сборка и запуск

Требуется Rust stable (MSVC) и Windows 10/11.

```powershell
cargo build --release
.\target\release\tm.exe
```

Для отладки удобен `cargo run -p tm-ui`.

GitHub Actions на каждый push в `main` проверяет `fmt` и `clippy`, собирает
release и выкладывает `tm.exe` артефактом `tm-windows-x64` во вкладке Actions.

### Права администратора

Диск и сеть **по процессам** собираются через ETW (`Microsoft-Windows-Kernel-
Network` и `Microsoft-Windows-Kernel-Disk`). Ядро Windows разрешает включать
эти провайдеры только администратору — так же ведут себя Process Hacker и
System Informer. Без прав обе колонки пустые, а в окне показывается кнопка
«Перезапустить как администратор» (UAC). Всё остальное работает без прав.

## Как устроено и почему быстро

* `crates/tm-core` — сбор данных без UI:
  * список процессов, потоки, CPU-время, память — **один** вызов
    `NtQuerySystemInformation(SystemProcessInformation)` на тик (~5-8 мс на
    500 процессов и 6500 потоков);
  * `GlobalMemoryStatusEx` для памяти (вместо медленного `GetPerformanceInfo`);
  * PDH с английскими именами счётчиков (`PdhAddEnglishCounterW`) — язык Windows
    не важен; GPU-счётчики (сотни экземпляров) опрашиваются раз в 3 тика, ёмкость
    дисков — раз в 10;
  * сеть — `GetIfTable2`, виртуальные/WFP-адаптеры отфильтрованы;
  * имена, описания, владельцы, elevation кэшируются по `(PID, время старта)`;
    после прогрева повторных дорогих вызовов нет;
  * ETW-сессия реального времени для диска/сети по процессам: события
    агрегируются в thread-local буфере и сбрасываются раз в 0.5 с, поэтому
    блокировки не мешают обработчику событий.
* `crates/tm-ui` — egui/eframe:
  * снимок публикуется атомарно через `ArcSwap`, UI никогда не ждёт сэмплер;
  * в кадре рисуются только видимые строки, тексты и числа форматируются
    на месте;
  * графики — из кольцевых буферов истории (600 точек), без аллокаций на кадр;
  * перерисовка раз в 200 мс, тема (светлая/тёмная) берётся из параметров Windows,
    шрифт — Segoe UI из системы.

Цифры на этой машине (i3-9100, 500+ процессов): сборка снимка ~7 мс (EMA),
старт до окна ~0.3 с, `tm.exe` ~4 МБ, RAM ~85 МБ, CPU ~0.5 % суммарно.

## Ограничения

* Число физических ядер показывается как число логических процессоров.
* Память GPU по процессам не выводится (только загрузка ГП).
* UWP-приложения могут отображаться именем процесса-хоста
  (`ApplicationFrameHost.exe`), если у него нет собственного окна.
* Защищённые процессы (антивирусы, `System`) не отдают путь/владельца — как и в
  оригинальном диспетчере.
* Для завершения процессов, запущенных от администратора/системы, нужны права.

## Диагностика

В `crates/tm-core/examples` есть утилиты:

```powershell
cargo run --release -p tm-core --example probe       # снимок и топ процессов
cargo run -p tm-core --example ident                 # доступ к процессам
cargo run -p tm-core --example actiontest            # завершение процесса
cargo run -p tm-core --example icontest -- <exe>     # извлечение иконки
# ETW-проверка (запускать от администратора):
cargo run --release -p tm-core --example etwprobe
```

Переменные окружения: `TM_PROFILE=1` — тайминги фаз сбора,
`TM_DEBUG_IDENT=1` — статистика кэша, `TM_DEBUG_ICONS=1` — счётчики иконок,
`TM_DEBUG_LAYOUT=1` — параметры окна, `TM_TAB=perf` — старт на вкладке
«Производительность».
